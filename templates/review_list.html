리뷰 CSV 가져오기

로컬에서 collect_reviews.py 를 돌려 만든 CSV를 올리세요. 같은 파일을 다시 올려도 안전합니다 — 새 리뷰는 저장하고, 이미 있는 리뷰는 「아직 살아 있다」고만 표시합니다(명세서 4장의 30일 재조회).

수집 방법 보기

제품 하나 · 대표 옵션만 (기본 1,000건 · 2~3분):

python collect_reviews.py --product "https://brand.naver.com/xxx/products/123456" --option "01. 헤이즐 IH 팬 24cm" --brand 도루코 --category 프라이팬

주 1회 갱신 — 지난 CSV를 주면 새 리뷰만 받고 멈춥니다(15초):

python collect_reviews.py --product "..." --option "..." --seen reviews_20260926_1055.csv

전수 수집 — 제품 등록 때 한 번만. 게시일 군집(체험단 살포) 판정용:

python collect_reviews.py --product "..." --option "..." --limit-reviews 0

⚠️ 수집은 로컬에서 사람이 돌립니다. 서버에 올려 자동 실행하지 마세요 — 실행 위치가 곧 성격이라, 서버가 정기적으로 긁는 구조는 약관 리스크가 다릅니다.

무엇이 어떻게 들어가나
1단 하드 배제서버에서 다시 계산합니다. 로컬과 어긋나면 수치가 달라지므로 DB 값은 서버 기준으로 통일합니다. 단 복붙은 리뷰 전체를 봐야 알 수 있어 CSV 값을 그대로 씁니다.
별점저장하지만 라벨 계산에 쓰지 않습니다. 리뷰 포인트 때문에 별점 5점에 「3개월 만에 코팅 벗겨졌어요」가 흔합니다. 텍스트와 어긋나는지 대조용입니다.
한달사용 배지내구성 문제(코팅박리·바닥변형·변색녹)의 분모입니다.
대표 옵션 불일치기록은 하되 라벨 계산에서 빠집니다. 28cm 팬 라벨에 24cm 후기가 섞이면 안 됩니다.
삭제 감지전수 수집분에서만 판정합니다. 표본 상한으로 1,000건만 모았다면, DB에 있고 CSV에 없는 것은 삭제가 아니라 「이번에 안 본 것」입니다.
랭킹순 수집분길고 사진 있고 추천 많은 리뷰가 앞에 와 통과율이 부풀립니다. sorted_latest=false 로 표시해 두고 라벨 계산에서 뺍니다.
